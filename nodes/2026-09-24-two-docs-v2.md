## v2 设计原则
1. 高密度，不做教材式灌水；每页必须能拿去决策/执行/复盘。
2. “事实 / 观察 / 假设 / 默认值”四分法，避免把经验写成算法真相。
3. 所有模板都必须有输入、输出、失败条件、下一步。
4. Director 文档从“术语库”升级为“Compiler + Production OS”。
5. Traffic 文档从“流量地图”升级为“Distribution OS + Experiment System”。
6. 两文档互相引用但可独立使用；Traffic 决定 why/where，Director 决定 how/when。
7. 交付前 DOCX 必须 render → 全页视觉 QA → 迭代。

## 2026-09-24 用户用途澄清：从“内容方法论”升级为“Agent 图约束工程”
用户明确：两份文档不是为了某个产品，也不是单次热点视频指南，而是未来交给“图约束工程 Agent”的长期执行规范。Agent 要能对任意输入对象（产品/品牌/人物/事件/服务/概念/行业/活动/甚至无既有热点的对象）执行：实时发现热点 → 判断窗口与可借势关系 → 必要时主动制造可传播事件/挑战/实验/叙事母题 → 编写脚本 → 生成图像约束包 → 生成视频约束包 → 调用不同图像/视频模型 → QA → 发布实验 → 数据回流 → 批量变体与持续生产。

因此下一版必须：
- 从“知识文档”重构为 Agent 可执行的 Graph Constraint OS；
- 明确节点、输入、输出、hard/soft constraints、Gate、fallback、状态、证据等级和失败分支；
- 实时性优先：把平台/模型事实做成可刷新 Adapter/Registry，核心逻辑保持 model/platform-agnostic；
- 不把“热点”理解为外部已有热搜：必须定义“热点发现 + 热点嫁接 + 热点重构 + 热点制造 + 热点自增殖”完整机制；
- 强化从脚本到 GPT/图像模型生成关键帧，再到视频生成模型的连续性约束、素材 manifest、角色/场景/物体 state、镜头 end-state handoff；
- 为未来全自动批量化保留机器可读结构（JSON/YAML schema / graph state / contract），同时 DOCX 仍作为人类可读总纲；
- 自由、大胆，但每个大胆选择必须有传播任务或叙事任务，不允许无目标炫技；
- 任何输入对象都应能经过“可传播性变换”寻找至少若干个可测创意假设，而不是只适用于 B2B/AI 产品。
